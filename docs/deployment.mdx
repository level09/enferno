## Overview

There are three ways to run Enferno in production: Docker Compose, a one-command VPS install with Ignite, or a manual setup.

## Docker Compose

The Compose stack runs the app under uWSGI with PostgreSQL, Redis, Celery and nginx:

```bash
./setup.sh --docker
docker compose up --build -d
docker compose exec website flask create-db
docker compose exec website flask install
```

`setup.sh --docker` generates `DB_PASSWORD` and `REDIS_PASSWORD`, which Compose requires, and sets `SESSION_COOKIE_SECURE=true`. For an existing installation, keep the passwords its database and Redis already use. nginx listens on port 80 and serves `enferno/static/` directly; PostgreSQL and Redis are not published to the host. Put TLS in front of it, or terminate it in nginx.

## Ubuntu VPS with Ignite

[Ignite](https://github.com/level09/ignite) installs an Enferno app on a fresh Ubuntu server with Caddy and automatic SSL, Redis, Celery, systemd services and a firewall:

```bash
curl -sSL https://raw.githubusercontent.com/level09/ignite/main/ignite.sh | sudo DOMAIN=your-domain.com bash
```

## Manual Setup

### Install

```bash
sudo apt update && sudo apt install -y nginx
curl -LsSf https://astral.sh/uv/install.sh | sh

git clone https://github.com/level09/enferno.git /srv/enferno
cd /srv/enferno
./setup.sh                    # Add --full for Redis and Celery
uv sync --extra wsgi          # uWSGI; include --extra full if you used it
uv run flask create-db
uv run flask install
```

In `.env`, set `FLASK_DEBUG=0` and, once HTTPS is in place, `SESSION_COOKIE_SECURE=true`.

### Database

SQLite works with no setup and lives in `instance/enferno.db`. For PostgreSQL:

```bash
sudo apt install -y postgresql
sudo -u postgres createuser -P enferno
sudo -u postgres createdb -O enferno enferno
```

```bash
# .env
SQLALCHEMY_DATABASE_URI=postgresql://enferno:password@localhost/enferno
```

Then run `uv run flask create-db` again. Enferno uses the `psycopg` 3 driver, which `uv sync` already installs.

### App Service

`/etc/systemd/system/enferno.service`:

```ini
[Unit]
Description=Enferno
After=network.target

[Service]
User=enferno
WorkingDirectory=/srv/enferno
ExecStart=/srv/enferno/.venv/bin/uwsgi --http 127.0.0.1:5000 --master --wsgi run:app --processes 2 --threads 2
Restart=always

[Install]
WantedBy=multi-user.target
```

```bash
sudo systemctl enable --now enferno
```

### Celery Service (Optional)

Only needed with `--extra full`. `/etc/systemd/system/enferno-celery.service`:

```ini
[Unit]
Description=Enferno Celery
After=network.target redis-server.service

[Service]
User=enferno
WorkingDirectory=/srv/enferno
ExecStart=/srv/enferno/.venv/bin/celery -A enferno.tasks worker --loglevel=info
Restart=always

[Install]
WantedBy=multi-user.target
```

### nginx and SSL

```nginx
server {
    listen 80;
    server_name your-domain.com;

    location /static {
        alias /srv/enferno/enferno/static;
        expires 30d;
    }

    location / {
        proxy_pass http://127.0.0.1:5000;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }
}
```

```bash
sudo apt install -y certbot python3-certbot-nginx
sudo certbot --nginx -d your-domain.com
```

## Production Checklist

- `FLASK_DEBUG=0`
- `SESSION_COOKIE_SECURE=true` behind HTTPS
- Secrets generated by `setup.sh`, never committed, `.env` readable only by the app user
- Migrations applied with `uv run flask db upgrade` on every deploy
- Database backups scheduled
- Only ports 22, 80 and 443 open

## Troubleshooting

- **Static files 404**: the nginx `alias` must point at `enferno/static` inside the project, and the nginx user needs read access.
- **App does not start**: `sudo journalctl -u enferno -e`. A missing `SECRET_KEY` or `SECURITY_PASSWORD_SALT` stops startup with a clear error.
- **Database errors**: check `SQLALCHEMY_DATABASE_URI` and that the database user owns the database.
- **Celery idle**: `sudo systemctl status redis-server`, and check `CELERY_BROKER_URL` in `.env`.
