## Project Structure

```
enferno/
├── enferno/
│   ├── app.py             # Application factory, blueprint registration
│   ├── settings.py        # Config from .env
│   ├── extensions.py      # db, migrate, cache, mail, session, CSRF, debug toolbar
│   ├── commands.py        # Flask CLI commands
│   ├── agent_mcp.py       # Read-only MCP server for coding agents
│   ├── public/            # "/" and OAuth handlers, no auth
│   ├── portal/            # "/dashboard/", login required
│   ├── user/              # Admin: users, roles, activity log
│   ├── tasks/             # Celery (optional)
│   ├── utils/base.py      # BaseMixin: save() and delete()
│   ├── static/            # Vendored Vue, Vuetify, axios, Tabler icons, app JS and CSS
│   └── templates/         # layout.html, admin pages, auth pages
├── migrations/            # Alembic revisions
├── tests/                 # pytest suite
├── instance/              # SQLite database
├── setup.sh               # Dependencies and .env with generated secrets
├── vendor.sh              # Pinned frontend library downloads
├── run.py                 # Entry point
├── AGENTS.md              # Instructions for coding agents
└── .agents/skills/        # enferno-dev agent skill
```

The full code patterns, with complete examples, live in the [`enferno-dev` skill](https://github.com/level09/enferno/blob/master/.agents/skills/enferno-dev/SKILL.md). This page covers the essentials.

## Blueprints

Each feature is a blueprint registered in `register_blueprints()` in `enferno/app.py`. Protect a whole blueprint in `before_request`:

```python
from flask import Blueprint, render_template
from flask_security import auth_required

portal = Blueprint("portal", __name__)


@portal.before_request
@auth_required("session")
def before_request():
    pass


@portal.get("/dashboard/")
def dashboard():
    return render_template("dashboard.html")
```

Admin blueprints add `@roles_required("admin")` under `@auth_required("session")`.

## Models and Migrations

Models use `BaseMixin` and implement `to_dict()` and `from_dict()`:

```python
from enferno.extensions import db
from enferno.utils.base import BaseMixin


class Post(db.Model, BaseMixin):
    __tablename__ = "posts"

    id = db.Column(db.Integer, primary_key=True)
    title = db.Column(db.String(255), nullable=False)
    content = db.Column(db.Text)
    created_at = db.Column(db.DateTime, server_default=db.func.now())

    def to_dict(self):
        return {"id": self.id, "title": self.title, "content": self.content}

    def from_dict(self, data):
        self.title = data.get("title", self.title)
        self.content = data.get("content", self.content)
        return self
```

After changing a model, draft a migration, read it, then apply it:

```bash
uv run flask db migrate -m "add posts"
uv run flask db upgrade
```

The test suite fails if a model and the migrations disagree.

## Queries

SQLAlchemy 2.x style, through Flask-SQLAlchemy:

```python
posts = db.session.scalars(db.select(Post).order_by(Post.created_at.desc())).all()
post = db.get_or_404(Post, 1)
page = db.paginate(db.select(Post), page=1, per_page=25)
```

## Admin APIs

Lists return `{"items": [...], "total": n, "perPage": n}`. Create and update take `{"item": {...}}`. Record admin changes in the activity log:

```python
from flask_security import current_user

from enferno.user.models import Activity

Activity.register(current_user.id, "Post Update", {"old": old, "new": post.to_dict()})
```

## Pages

Pages extend `layout.html`, mount their own Vue app with `layoutMixin`, and use `${ }` for Vue expressions, since `{{ }}` is Jinja. The frontend is Vue 3 and Vuetify 4 with no build step:

- Icons are Tabler only (`ti-*`); `mdi-*` icons render blank.
- Use Material Design 3 type classes such as `text-headline-small` and `text-body-medium`. Vuetify 3 names like `text-h5` and `text-caption` no longer exist.
- Icon-only buttons need an `aria-label`.
- Pass server data with `<script type="application/json">{{ data|tojson|safe }}</script>`.

## Background Tasks (Optional)

```bash
uv sync --extra full
```

```python
from enferno.tasks import celery


@celery.task
def send_report(user_id):
    ...
```

```bash
uv run celery -A enferno.tasks worker --loglevel=info
```

`enferno.tasks.celery` is `None` when Celery is not installed or configured.

## Checks

```bash
uv run ruff check --fix . && uv run ruff format .
uv run pytest
```

The suite checks that every protected route rejects anonymous users and non-admins, that models match migrations, CSRF, the auth flows and `setup.sh`. For UI changes, also click through `/dashboard/` and `/users/` as an admin.

## Debugging

The Flask Debug Toolbar is wired in; enable it with `DEBUG_TB_ENABLED=1` in `.env`. To log SQL:

```python
import logging

logging.getLogger("sqlalchemy.engine").setLevel(logging.INFO)
```
